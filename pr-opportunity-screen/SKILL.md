# Pattern Recognition opportunity screening

Use after a venue study or when the user brings an application failure and asks for paper opportunities. A planning request authorizes literature work and plans, not model calls, benchmark runs or robot operation. Keep the formal paper topic uncommitted until evidence warrants it.

## Establish what the problem actually is

Distinguish user-reported failure, direct observation, paper-reported evidence, and your proposed explanation. For video evidence, record inspected time ranges and missing sensor/log information. A robot leaving an object untouched does not identify which of sensing, recognition, pose, planning or execution failed.

Translate an application requirement into an observable input–output problem, supervision and deployment conditions. Keep procurement goals and achieved metrics separate. Physical shipping labels and multi-label classification are different concepts. An available model API or an interest in SNNs does not establish scientific fit.

For sensing proposals, distinguish absent measurements from plausible but biased measurements. Identify the sensor principle and available channels before designing a solution. SNNs are model families; event cameras are sensors. A frame-to-spike encoding does not create native event observations, and a spike-operation estimate does not measure device energy.

When code, device manuals or system logs accompany the failure, use [static material evidence](references/static-material-evidence.md) to distinguish documented capability, implementation behavior and actual field evidence before attributing a scientific cause.

## Attack novelty before designing modules

For each lineage, search the task, mechanism, mathematical operation, failure condition, adjacent-field terminology, and newest public preprints through a stated cutoff. Include older decisive prior art. Verify publication state through primary publisher or proceedings evidence; keep inaccessible and abstract-only sources visible.

Use public, generalized search terms. Do not send private source URLs, company identifiers, raw examples or unpublished mechanism details to external search services unless the user's existing authorization covers that disclosure. When a closest work is only available as an abstract, mark unverified mechanisms and protocol fields unknown; do not certify a gap from missing abstract detail.

Extract inputs, label access, target-image access, pretraining, validation feedback, adaptation, budget and evaluation from the closest works. A training-free method can use target labels or cross-image statistics. Group comparisons by actual information access rather than their method names.

Put the strongest prior-art threat and simplest repair before the proposed contribution. Common controls include fixed mixing, graph freezing, damping, exposure adjustment, mask thresholds, ordinary temporal models and existing prediction calibration. A missing table, reporting ambiguity or implementation correction is not automatically a research gap.

Read [screening lessons](references/screening-lessons.md) when a plausible idea resembles a known operation. Search again after narrowing the mechanism. “No direct hit” only describes the search envelope; it does not prove firstness.

## Write a candidate that can lose

Use the [candidate and protocol template](references/candidate-protocol-template.md). State:

- The condition, broken assumption, observable failure signature and intervention.
- What is already established, what is inferred, and what remains a hypothesis.
- The smallest proposed technical difference from the nearest mechanism, including any extra information it needs.
- A prediction that separates it from a simple explanation, and outcomes that would kill or reframe it.
- A primary endpoint, independent unit, matched controls, data/split plan, uncertainty method, practical effect threshold and resource ceiling.

Check identifiability: if two latent worlds produce the same allowed observations but demand different decisions, no confidence heuristic can reliably distinguish them without added assumptions or information. State those assumptions; do not promise to recover unseen geometry or shared errors from agreement alone.

Preserve competing hypotheses and negative cases. If a proposed gate only reduces coverage, compare risk at matched coverage. If it uses additional frames, labels, sensors, tuning or runtime, give those resources to appropriate controls or put it in a separate comparison group.

## Deliver a decision, not invented readiness

Rank candidates by significance, unresolved mechanism, prior-art threat, informative falsifier and accessible assets. Keep scientific importance separate from immediate execution readiness. Use explicit decisions such as `REJECT_GENERIC_VARIANT`, `RESERVE`, or `PRIORITIZE_FOR_FALSIFICATION`; none means novelty established or experiments passed.

Deliver a source/read-depth ledger, query log, nearest-work matrix, candidate cards, draft protocols, resource unknowns, concrete collaboration tasks and an independent challenge report. Cost and hardware figures remain estimates until measured. A repository link or registered server is not proof that a baseline can run.

During planning, do not label protocols frozen or externally preregistered. Do not apply an exact-match classifier validator to mAP, clustering or segmentation metrics. Match the future statistical design to the real unit: object/session, full image, patient, dataset and training seed are not interchangeable.

Keep enterprise source material and unpublished candidate mechanisms in the authorized private destination. Public reusable skills should contain generalized procedure and published-work lessons. Follow the user's existing source-access and publication rules; this skill grants no new permissions.
