# ICDE-style review form (simulation: ICDE publishes no official form)

Paper: <title>            Reviewer lens: <method/theory | systems/experiments | generalist>

EAB / benchmark paper? Use the EAB form, checklist and limitations lens in `references/eab.md` (sections 1-5).
It replaces the score row below with: novelty of insights, soundness, coverage, reproducibility (hard
requirement), usefulness, presentation and relevance.

1. **Summary** (3-5 sentences, in your own words: problem, approach, evidence).
2. **Strengths**
   - S1
   - S2
   - S3
3. **Weaknesses** (each must say what would fix it)
   - W1
   - W2
   - W3
4. **Detailed comments** by section (Introduction, Problem, Method, Experiments, Related Work).
5. **Scores** (1 = poor ... 5 = excellent)
   Official anchors: relevance/positioning, supplemental availability, EAB insight, inclusive writing.
   The other columns are a simulation.
   | Novelty | Technical depth and soundness | Experiments | Presentation | Reproducibility (artifacts) | Relevance to ICDE |
   |---|---|---|---|---|---|
   |  |  |  |  |  |  |
6. **Overall**: Strong Accept / Accept / Weak Accept / Weak Reject / Reject
7. **Confidence**: 1 (guess) ... 5 (expert)
8. **Three most likely reasons this paper would be rejected**
9. **Requested experiments** (this is a pre-submission review, so ask for whatever would change your
   score). Give one row per request:

   | # | Type (add / supplement / remove / re-run) | What exactly | Which weakness it answers | Rough cost | Result that would raise your score |
   |---|---|---|---|---|---|

10. **Presentation of limitations**:
    - Is each negative result stated once, with a mechanism, in the experiment that measures it?
    - Does the abstract, introduction or conclusion repeat losses or use self-negating wording ("does
      not help", "vanishes", "only N×")?
    - Does any sentence contradict a table?
11. **Questions for the authors (rebuttal)**
