\section{Introduction}
Rolling restarts of a gateway's control plane are routine, yet every restart of a coupled
gateway terminates requests that straddle it. Figure~\ref{fig:demo} contrasts the two
behaviours on one shared time axis, so the reader compares a single variable: what happens
to requests that are in flight at the restart instant~$t_r$.

\caption{\textbf{An epoch-pinned data plane makes control-plane restarts invisible to in-flight
requests.} Both lanes replay the same four requests. Top: the coupled gateway drops the two
requests that straddle $t_r$ and is unavailable for a while (shaded). Bottom: in-flight requests
finish on epoch~$e$ while a new request is served by $e{+}1$ (\textcolor{tvfOurs}{blue}) without waiting.}
\label{fig:demo}

The figure follows the rules of the accompanying style file: one accent hue for the
contribution, one alert hue for the failure, neutral gray for everything shared; labels sit
beside the marks they name; numbers are placed where the eye ends each lane; the caption opens
with the claim. Nothing in the figure is boxed for the sake of boxing.

When an architecture view is genuinely needed (usually Figure~2 or~3, not Figure~1),
Figure~\ref{fig:demo-arch} shows the container and edge styles: the container has a title band
that no edge crosses, external edges end on the container border, internal edges are
orthogonal ($|\!-$ / $-\!|$ paths) and every edge label sits in whitespace beside its line.
