# 双门循环（Gate A：全指标胜过每个 baseline；Gate B：与已发表范文对齐）

## 角色

- **Reviewer**：只判定锁定版本，写修改请求；不改稿、不改代码、不跑新的开发实验。
- **Fixer**：改方法、实验或文字，交付新的锁定版本；不能自己批准自己的修改。
- 同一轮里两个角色不能由同一个执行者担任。复审由另一次独立的 reviewer 执行（新会话或新代理），只看新版本与上一轮的修改请求清单。
- 绝不输出录取概率；只输出 met / partial / gap、PASS / FAIL 与可验收的修改请求。

## Gate A：方法在每个报告指标上胜过每个 baseline

### 构建矩阵

1. **列出全部指标**：稿件正文、表、图、宏文件、artifact 和 DEV 结果里出现的每个指标。数据校验类论文的典型指标：检测数/检测率（按故障类型）、误报数/误报率（按干净运行）、未定义/放弃作答（abstain）计数、覆盖率、总 CPU、总 wall time、p50/p95/p99 延迟、扫描行数/字节、额外查询数、内存、启动/派生（静态分析）成本、生命周期总成本、预算内可部署检查数、各规模/各数据类型分块结果。
2. **列出全部 baseline**：每个外部已发表方法（或其忠实重实现）、每个强精确对照（如完整比对）、每个廉价对照（如只做 guard 的检查）、每个自家弱化变体与组合成员。**方法输给自己更简单的变体，说明算法有缺陷**。
3. **逐格判定**：每个（指标 × baseline × 分块）给 W / T / L，并给总量与成对置信区间（有重复测量时）。
4. **每行分类**：
   - PASS：所有格都胜；
   - PARTIAL：有平局、无负；
   - FAIL：任一格负；
   - MISSING：该指标没有对所有 baseline 测量；
   - NOT EVALUATED：只对本方法报告。

### 规则

- **平局**：只有当稿件**证明**该格处在任何方法都无法超越的界限时才算"未被击败"——例如误报率 0%（不可能更低）、检测率 100%（不可能更高）、或可证明的下界（必须读的最少字节、预算下的离线最优）。其他平局一律视为未通过，要求算法改进。
- **安全约束**：误报、漏检、错误放行属于正确性约束。在安全方法之间零对零的平局可接受；本方法任何非零误报或在已承诺类别上的漏检都是阻断。
- **放弃作答的对照**：如果某对照在部分输入上放弃作答（abstain）而显得更便宜，成本对比必须同时报告：全部输入的总量、双方都作答的子集、每检出一个故障的成本。是否改用其中某个口径作为判据，由作者在打分前预先登记决定；在作者决定前，按最严口径（全部输入总量）判定。
- **代理指标**：计数代理（检查数、查询数）不能替代实测成本；"更少的查询但每个更贵"在实测时间上算 FAIL。建模出来的成本永远不能替代实测成本。
- **启动成本**：派生/静态分析/编译成本若被排除在后缀总量之外，必须另报生命周期总量并参与比较。
- **对照公平性**：对照的实现若在本轮被修改（例如换了更慢的数值比较），必须先恢复为等价的高效实现再比较；不公平对照下的胜利不计。
- **DEV 与 TEST**：DEV 结果只用于指导设计；只有预先登记、按哈希冻结、在未见过的种子上只评估一次的 TEST 结果才能作为头条。

### FAIL / PARTIAL / MISSING 行的修改请求

每个请求写明：
(a) 根因——用稿件自己的机制解释为什么输（例如：廉价对照只跑一次 guard 就放弃；在大规模分块上逐行成本占主导）；
(b) **算法层面的改动**（合并扫描、改变检查派生顺序、预算感知的提前终止、精确比对的快速路径等）；
(c) 验收测试（哪个网格、哪些 baseline、哪个指标、逐格与总量的判据）；
(d) 协议（先在 DEV 预登记，按哈希冻结，在新种子上评估一次）。

改写措辞、缩小声明、删掉指标、移到附录，都**不能**关闭 Gate A 行。

## Gate B：与已发表范文对齐

按 `review-procedure.md` 从标题走到参考文献，逐节逐段判 met / partial / gap（带 文件:行号 证据），对照 `fingerprints.md` 的区间，检查第 11 节的阻断条件。任何 blocking 或 major 发现都要写成修改请求，要求具体的修订（改哪一段、改成什么结构、以哪篇范文的哪一处为样板、如何验收）。

## 每一轮

1. **锁版本**：PDF 哈希、源码哈希、artifact/DEV 哈希、页数。
2. **Gate A** 矩阵 → 每个非 PASS 行一个算法层面的修改请求。
3. **Gate B** 逐节审查 → 按影响排序的发现（blocking / major / minor）。
4. **修改请求清单**：`ID | gate | severity | 位置（文件:行号） | 范文证据 | 要求的改动 | 验收测试`。ID 跨轮稳定，不得悄悄删除任何请求。
5. 把清单和版本哈希交给 fixer。

## 复审下一次交付

- 核对新哈希；核对冻结的 TEST/gold/scorer/头条数字在冻结后没有被调。
- 对每个未关闭的 ID：CLOSED（在新版本上满足验收测试，附证据）、OPEN、REGRESSED。
- Gate A 行只有新的实测结果才能关闭；文字修改永远不能关闭。
- 每轮重跑完整的 Gate A 矩阵——修复可能破坏别的指标。

## 批准

只有当每个 Gate A 行为 PASS（或平局处在已证明的界限），且没有任何 blocking/major 的 Gate B 发现时才批准。任一门未过：发出下一组最小的具体要求，进入下一轮；**不降低门槛，不宣布放弃**，也不把"已交付"当作"已通过"。
