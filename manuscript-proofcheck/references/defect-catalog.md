# Defect catalog

Each entry: what the reader sees, the root cause, how the scripts detect it, and the fix. Rule ids
match `scripts/tex_lint.py` (T*) and `scripts/pdf_check.py` (P*). Entries marked *observed* were found in
a real compiled submission.

## Glyphs and symbols

### T01 / P01 Wrong glyph for the indicator 1 (*observed*, TopUp, ICDE 2027)
- Seen: `e = ⊮[A(t)=r]`, i.e. a turnstile-like symbol (U+22AE) instead of a blackboard-bold one.
- Cause: `\mathbb 1` or `\mathbb{1}` with amssymb/amsfonts. The `msbm` font only has upper-case
  letters, so the slot for "1" holds an unrelated relation symbol.
- Detect: source regex `\mathbb\s*\{?\d`; PDF text contains U+22AE.
- Fix: `\usepackage{dsfont}` and `\mathds{1}`, or `\usepackage{bbm}` and `\mathbbm{1}`, or plain
  `\mathbf{1}`. Define one macro (e.g. `\newcommand{\ind}{\mathds{1}}`) and use it everywhere.

### T02 Unicode characters in source compiled with pdfLaTeX
- Seen: missing characters or compile errors (×, –, ’, ≤ typed directly).
- Fix: use LaTeX commands (`$\times$`, `--`, `'`, `$\le$`), or compile with a Unicode engine the venue allows.

## Bibliography

### T03 / P03 Dash instead of repeated author names (*observed*)
- Seen: `[15] ——, "Optimized stratified sampling …"` directly after an entry with the same authors.
- Cause: IEEEtran.bst replaces an author list that repeats the previous entry's with a 3-em dash by
  default (`CTLdash_repeated_names = "yes"`). This is legal IEEE style, but readers often take it for a
  rendering error, and it hides authorship when entries are cited out of order.
- Detect: IEEEtran bibliography style without a BST control entry; PDF reference line starting with a
  dash.
- Fix: add to the `.bib`
  ```
  @IEEEtranBSTCTL{IEEEexample:BSTcontrol,
    CTLdash_repeated_names = "no"
  }
  ```
  and put `\bstctlcite{IEEEexample:BSTcontrol}` right after `\begin{document}`. For biblatex use
  `dashed=false`. For other `.bst` files, check their options.

### T04 "et al." or "and others" in a self-citation
- Cause: the bib entry was written before the author list was known.
- Fix: list every author. Under double-blind review, use the venue's anonymisation rule instead.

### T05 Unverifiable or impossible entries (*observed*: an "ACL 2026" DOI for a 2024 arXiv paper)
- Cause: bib entries copied from memory or generated by a model.
- Detect: the year is later than the current year, a DOI prefix does not match the venue, a "2026"
  publication of a known arXiv paper. The lint only flags candidates; online verification decides.
- Fix: replace the entry with the record from DBLP, the ACL Anthology or the publisher. If no published
  version exists, cite the arXiv version.

### T06 Entry fields
- Missing `year`, missing `pages` for journals, `howpublished` misused for published work, duplicate
  keys, inconsistent venue abbreviations (`Proc. VLDB Endow.` vs `PVLDB`). Pick one abbreviation
  scheme for the whole list.

## Theorems and proofs

### T07 Foreign QED box with IEEEtran (*observed*)
- Seen: an open square □ at the end of each proof, unlike the closed box of IEEE papers. Readers flag
  it as a stray glyph.
- Cause: `amsthm` loaded with IEEEtran. amsthm's `proof` uses `\openbox`, and the IEEEtran
  documentation advises against amsthm because the two theorem implementations conflict.
- Detect: `\documentclass{IEEEtran}` together with `amsthm`, or `\begin{proof}`.
- Fix: drop `amsthm`. Keep `\newtheorem{theorem}{Theorem}` (IEEEtran formats it), and replace
  `\begin{proof}[Proof sketch]…\end{proof}` with `\begin{IEEEproof}[Proof sketch]…\end{IEEEproof}`.
  Remove `\qedhere`; IEEEtran places the mark itself (`\IEEEQEDhere` if needed).
- Update (2026-11-06, observed): after this fix, IEEEtran's default *closed* box ■ was flagged as a
  garbled glyph too. Also add `\renewcommand{\IEEEQED}{}` after the packages, so that no end-of-proof
  mark is printed, unless the venue template mandates one. `manuscript-writing-review` checks this
  in the source (R04) and in the PDF (L05).
- Other classes: acmart and llncs already load their own proof environments, so do not load amsthm on
  top of them.

## Title, authors, front matter

### T08 / P08 Hand-made line break in the title (*observed*)
- Seen: a four-line title with a two-word line ("LLM Labels") and a one-word last line ("Data").
- Cause: `\\` inside `\title{}` forces a break where it fits one page width but not the class's.
- Fix: remove `\\` and let the class break the title. If a break is required, use `\\` only at a
  phrase boundary and check the compiled result.

### T09 TODO, placeholder or coloured draft text left in
- Detect: `\todo`, `TODO`, `XXX`, `\textcolor{red}`, `[citation needed]`; PDF spans in non-black colour.

### T10 Author block
- Must match the submission system exactly (order, spelling, affiliations). Use the class's macros
  (IEEEtran: `\IEEEauthorblockN/A`, `\IEEEauthorrefmark`, and `\thanks` with
  `\IEEEoverridecommandlockouts` for a corresponding-author note).

## Math layout

### T11 Tall inline math pushes into the previous line (*observed*)
- Seen: the overline of an inline `\sqrt{\sum …/…}` touches the text line above, which looks like
  underlining.
- Cause: inline radicals, `\frac`/`\dfrac` and big operators with limits enlarge the line height.
- Fix: move the formula to a display, or rewrite inline as `(\cdot)^{1/2}` with `\sum\nolimits` and a
  slash fraction.

### T12 Display whose continuation floats far right
- Cause: `multline` right-aligns its last line. With a short first line in a narrow column, the
  formula looks broken.
- Fix: `align*` with `&` at the left of both lines and `\quad` before the continuation, or `split`.

## Spacing and page budget

### T13 Spacing hacks (desk-reject risk)
- Negative `\vspace`/`\vskip`, `\baselinestretch` < 1, `\setlength{\textheight}`, `geometry`,
  `\titlespacing`, `\abovedisplayskip` changes, `\small` around body text, `\linespread`.
- Fix: remove them and cut text. Never trade layout rules for space.

### P13 Page budget
- `pdf_check.py` ends the body at the first heading that the venue excludes from the limit: the references, or an AI-generated content acknowledgment placed before them (ICDE 2027 excludes both).
- Count body pages the way the venue does (e.g. the main text up to the references, or everything).
  `pdf_check.py --body-limit N` compares the page holding the reference heading with N.

## Cross-references and text

### T14 `\cite`/`\ref` without a non-breaking space
- `word \cite{x}` can break the line before "[12]". Use `word~\cite{x}` and `Table~\ref{t}`.

### T15 Unreferenced float or label
- Every figure, table and algorithm label should be `\ref`'d in the text.

### T16 Inconsistent spelling variety
- Mixed `labelling`/`labeling`, `-ise`/`-ize`, `modelling`/`modeling`. Pick the venue's variety.

### T17 Repeated word
- "the the", "a a", "of of", also across a line break in the source.

## Fonts and PDF

### P17 Type 3 or non-embedded fonts
- Usually from matplotlib (set `pdf.fonttype = 42`) or old figures. IEEE PDF eXpress and some
  publishers reject non-embedded fonts.

### P18 Stretched reference entry from a long unbreakable URL
- Seen: a reference whose words are spread far apart across the column (e.g. "X. Zhang, J. Zhao,
  and Y. LeCun"), followed by a long hash-like URL. Cause: the URL has few break points, so the
  justified lines above it absorb the slack.
- Detection: visual pass over the reference pages; source check for `url =` fields over ~60
  characters in `.bib`.
- Fix: drop the URL when the entry is fully identified by venue, volume and year (proceedings
  papers), or load `\usepackage[hyphens]{url}` / `xurl` so the URL can break.

## Floats and layout (observed in an ICDE 2027 EAB submission, Agent-RLS)

### T18 / P19 Table wider than its column (*observed*)
- Seen: the last columns of a single-column table run into the right margin and are cut off
  ("Policy in p", rotated headers "latency / $" and "public schemas" past the page edge).
- Cause: a `table` (one column, about 8.9 cm in IEEEtran) holding many columns or long cell text;
  headers rotated by 45-70 degrees occupy more horizontal space than their column, so the rightmost
  headers overhang even when the body fits.
- Detect: source: `\rotatebox{θ}` with θ ≠ 90 inside `table`, or a single-column `tabular` with 5 or
  more columns and cells longer than ~28 characters (T18, a warning to check). PDF: any text span whose
  right edge lies within 36 pt of the page edge (P19, an error).
- Fix: rotate headers by 90 degrees and shorten them; shorten cell text (put long notes in a
  footnote line under the table); or make the float `table*`. Do not shrink with `\resizebox` below
  the caption font size, and never change margins.

### T24 Rivers in narrow justified table columns (*observed*)
- Seen: "acctbal, phone, address" or "region / global revenue, orders per year" spread over a narrow
  cell with large gaps between words.
- Cause: `p{w}` columns are justified; with `w` below ~2.5 cm there are too few break points.
- Detect: `p{...cm}` narrower than 2.5 cm in a `tabular` spec.
- Fix: `\usepackage{array}` and `>{\raggedright\arraybackslash}p{w}`.

### T19 Text placed between a theorem and its proof (*observed*)
- Seen: "Proposition 2 ... ." then an unrelated sentence, then "Proof sketch." The proof reads as if it
  belonged to the sentence.
- Cause: a remark inserted during revision directly after `\end{proposition}`.
- Detect: non-environment text between `\end{theorem|proposition|lemma|corollary|claim}` and the next
  `\begin{proof|IEEEproof}`.
- Fix: move the remark after the proof.

## Bibliography generated from Crossref or arXiv metadata (observed, Agent-RLS)

### T20 Acronyms lower-cased in titles (*observed*)
- Seen: "Auditing sql queries", "Duckdb", "Mcptox", "Rls side channels", "Securesql".
- Cause: IEEEtran.bst (and plain, abbrv, unsrt) convert titles of articles and proceedings papers to
  sentence case; only text in braces keeps its case.
- Detect: an unbraced word with two or more capitals in `title` under a case-changing style.
- Fix: brace the acronyms (`{SQL}`, `{DuckDB}`), or the whole title (`title = {{...}}`) to keep the
  published capitalisation. Apply the same rule to every entry so the list looks uniform.

### T21 Non-ASCII first letter of a name mangled (*observed*)
- Seen: "ore Klisura" for "Đorđe Klisura".
- Cause: BibTeX abbreviates given names byte-wise; a UTF-8 first letter outside its alphabet is lost.
- Detect: a given name whose first character is non-ASCII.
- Fix: write the name with TeX accents or commands: `{\DJ}or{\dj}e`, `{\'E}mile`, `{\v{S}}tefan`.

### T25 Text command missing in the default font encoding (*observed*, after an uncompiled T21 fix)
- Seen: `! LaTeX Error: Command \DJ unavailable in encoding OT1`. Overleaf still produced a PDF and the
  reference showed a wrong or missing letter, so the author saw no error.
- Cause: `\DJ`, `\dj`, `\NG`, `\TH`, `\DH` are defined only in T1; IEEEtran and many templates stay in OT1.
- Detect: tex_lint T25 (one of these commands in the source or bib and no `\usepackage[T1]{fontenc}`); the
  compile log.
- Fix: `\usepackage[T1]{fontenc}` in the preamble. Lesson: a fix to a bib entry is not done until compiled.

### T22 Crossref records copied verbatim (*observed*)
- Seen: "ser. SIGMOD/PODS04", "Springer Berlin Heidelberg" with no proceedings title, long
  `http://dx.doi.org/...` URLs under every entry.
- Cause: Crossref's BibTeX transform emits `@inbook` for proceedings chapters (IEEEtran then ignores
  `booktitle`), `series`/`collection` fields with internal labels, and a `url` that repeats the DOI.
- Detect: `@inbook` with `booktitle`; `series`/`collection` with such labels; `url` containing
  `doi.org` next to a `doi` field.
- Fix: use `@inproceedings` (or `@incollection` for edited books), drop `series`, `collection`,
  `url`, `ISSN`, `ISBN`, `editor` (journal editors), and keep the DOI. Normalise in the script that
  generates the `.bib`, so a regeneration does not bring the defects back.
- Also: one-line entries (`@article{key, title={...}, ...}`) are valid BibTeX. The linter reads
  entries by brace matching, so they are no longer reported as missing.

### T23 Placeholder author block or link (*observed*)
- Seen: "Author names withheld in this draft", "Affiliation to be completed",
  `https://github.com/ANONYMIZED/...` in a single-blind submission.
- Detect: source and PDF text patterns (`names withheld`, `to be completed`, `ANONYMIZED`).
- Fix: fill the real block from the submission system data (names, affiliations, e-mails, ORCID in
  the system), and the real artifact link, unless the venue is double-blind.
