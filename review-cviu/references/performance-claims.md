# 性能主张的核查

以下为实现与报告建议，不是 CVIU 官方硬性实验清单。只针对会影响当前主张的事实提出动作，不自动要求所有论文增加所有实验。

1. **比较身份与口径。** 最近强方法是否是真实正式版本？结果来自作者表、完整重跑、平台移植还是共同骨干策略替换？输入、监督、初始化、分辨率、预算及端点相同时才可直接比较；不同设置不应通过方法名称掩盖。
2. **实现迁移。** 核对实际像素中心、梯度单位、阈值、运算顺序和优化状态。移植一致性证据与算法增益证据分开；共同骨干修复也应与新增方法分别定位。
3. **开发与确认。** 查看候选和选择依据是否完整，确认矩阵是否在其结果出现前固定。历史看过的目标不再标为全新未见数据；前后阶段的目的与数据使用如实说明。
4. **指标独立性。** 主端点是否对应研究任务？派生自同一误差的多个指标不能当作独立多数投票。核全部约定端点、逐场景配对幅度和成本，避免以少量胜场掩盖主要端点或关键条件的退化。
5. **条件机制。** 场景强弱条件是否事先定义或不依赖方法结果？解释使用的是相关性、受控干预还是同状态比较？相机、帧、状态、种子和独立场景不能互相替代样本量。事后发现可以提出假设，不能改称事前预测。
6. **成本范围。** 同步数、同容量与同时间不是同一公平性假设；并发调度耗时不能直接写成独占算法速度。核硬件、计时起止、预处理/共享开销及实际峰值内存。

将具体问题转成最小动作：补齐已有原始标量、修正比较标签、核对移植语义、增加一项能区分解释的对照，或收窄超过证据的主张。已完成且有效的不利结果保留。不要因为希望达到 SOTA 就预先写下成功结论，也不要把一个有条件的改善夸成普遍优越。
