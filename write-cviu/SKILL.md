# Write-CVIU

本技能提供写作判断，不能替代投稿当日的官方格式要求。使用前读 [references/examples.md](references/examples.md)；范文观察、本文建议和官方硬性规则必须分开。公开发表不说明某种措辞导致录用，也不能据此承诺录取率。

## 先确定论文实际上解决什么

1. 用一句话写清输入、视觉任务、关键困难、技术干预和可测输出。
2. 建立“主张→最接近工作→实际差异→实验/图表→适用条件”表。把未验证的主张改为待验证项，避免用更强形容词替代证据。
3. 准确区分使用现有模块、组合方式的新意和新增算法；检索方法简称是否与邻近工作冲突。
4. 用户要求先审计划时，先交付可审阅修改表（原文位置、建议、理由、证据、数据依赖），在用户批准前保留原稿。

## 按证据组织稿件

- **题名**：优先“对象/任务 + 关键机制”，可加唯一且必要的简称；只把有直接验证的能力放进题名。避免同时许诺鲁棒、实时、高保真和泛化，却没有相应证据。
- **摘要**：任务与具体不足→核心机制→实验范围→最有信息量的实际结果。交代结果相对于何种基线、何种协议；没有统计支持时写描述性差异。
- **引言**：从可见的视觉问题进入，以一个可复核例子说明困难；对最接近方法的评价必须准确。贡献项目分别对应可定位的机制或验证。
- **相关工作**：按技术假设、输入/监督条件和待解决问题组织；对同任务最近邻作实质比较。不要按期刊或引用数量堆文献。
- **方法**：先给输入输出和整体图，再给新增机制；补全坐标系、变量维度、目标函数、采样/离散操作、训练时机、推理依赖。已有算法简述并引用原出处。
- **实验**：协议、指标、实现及硬件→主比较→直接验证机制的消融→成本→困难条件。每一小节先写它回答的问题，再给结果和解释。区分训练视图与测试视图、人物与图像、随机种子与相机样本。
- **讨论与结论**：集中说明实测边界和代价，删重复的笼统自我否定；保留影响结论的事实。结论回到问题与已验证贡献，不新增能力承诺。

## 图表怎样支撑判断

为图表分别写一句“读者看完应能判断什么”。采用实际输出和明确样本ID；跨方法使用相同视角、帧、裁剪坐标、缩放与颜色范围。局部放大需有全图定位，图注说明比较条件和所见现象。方法图区分数据流、梯度流、固定先验和可学习参数，不能给离散操作虚画梯度。

主表呈现全部预定指标、方向、单位、监督/预算差异和聚合方式。性能与资源表配合阅读；含额外模块的方法，应量化对应的训练和推理代价。消融用可以隔离假设的对照，必要时约束点数、参数量或运行预算，避免把增加资源所得提升全归因于新机制。

## 有力而准确的措辞

用“在任务T、协议P上，相对基线B，指标M改善X”代替笼统“全面优于”。说明优势所在，也保留完整结果供核对。仅有渲染质量改善时，不自动写成几何、语义或解剖正确性已证明。

删冗余负面修辞与隐去重大反结果是不同操作：若结论依赖额外监督、特殊初始化、数据筛选或更多资源，应明确相应条件；不伪造实验、统计显著性、可用代码或数据声明。无法确定实现的公式问题返回代码/作者核对，不能靠调整符号猜测算法。

## 交付检查

交付改写稿或计划时同时给出：主张—证据表、逐项修改记录、仍需数据/实验的清单。检查题名、摘要、贡献、图注、主表和结论是否一致；核对引用是否确实支持相邻论断。格式、匿名、声明和材料清单再按当前 CVIU 官方指南核验；本技能不授权提交、发送或公开发布。
