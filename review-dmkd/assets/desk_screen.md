# DMKD desk screen (editor-in-chief, simulated)

## Hard gates (any "no" = returned to authors)
- [ ] Complete editable source set (LaTeX zip with figures, class and bibliography) and compiled PDF
- [ ] Abstract 150-250 words, no undefined abbreviations or citations; 4-6 keywords
- [ ] "Statements and Declarations" section with funding, competing interests, ethics/consent, data, materials and code availability, author contributions
- [ ] Data availability statement with repository and persistent identifier
- [ ] LLM use documented in the Methods section if beyond copy editing
- [ ] Not under review elsewhere; any prior version declared with a statement of what is new
- [ ] Article type selected deliberately (Regular / Survey / Application)

## Substantive screen (any "no" = likely desk reject)
- [ ] Scope: framed as a KDD problem (data cleaning, evaluation validity, KDD-process reproducibility); cites DMKD/KDD/ECML PKDD/JMLR work
- [ ] Contribution and its type visible in the abstract; one-sentence claim possible
- [ ] Research gap: why existing evaluation studies do not already answer the question
- [ ] Consequence: at least one demonstration that the problem changes a reported result, ranking or conclusion
- [ ] Breadth: more than one system, benchmark or consumer, or a convincing argument why one suffices
- [ ] Research questions stated; methods replicable; artefact archived with a DOI
- [ ] Fair tone toward audited systems
- [ ] Readable by a data-mining generalist; length proportionate
- [ ] Suitable action editors exist (name two or three) and the paper engages their work

Decision: <send to action editor | return for completion | desk reject>, with a two-sentence reason.
